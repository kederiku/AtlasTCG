# Tests manquants et CI — plan d’exécution

> **For agentic workers:** Use superpowers:executing-plans for implementation and
> superpowers:test-driven-development for any reproduced regression.

**Goal:** Protéger les comportements existants insuffisamment testés et aligner
GitHub Actions sur les vérifications documentées.

**Architecture:** Conserver les frontières et les outils actuels. Tester les effets
observables avec bases temporaires, HTTP local et transport simulé pour React.
La CI appelle les cibles Make, sans dépendre d’un fournisseur de cartes.

**Tech Stack:** pytest/pytest-bdd, Vitest/Testing Library, uv, Make, Compose et GitHub Actions.

**Spec:** [Contrat d’acceptation](../../acceptance.md), [règles](../../engineering.md),
[contribution](../../../CONTRIBUTING.md) et demande d’audit des tests/actualisation CI.

## Contraintes

- Préserver le workflow `.github/workflows/ci.yml` déjà présent mais non suivi.
- Aucun commit, publication, migration personnelle ou arrêt des services existants.
- Ne pas ajouter une dépendance ou un seuil de couverture pour gonfler un indicateur.
- Les tests de caractérisation peuvent être verts immédiatement ; aucun échec artificiel.
- Si un test révèle une régression, lire l’échec avant la correction minimale.
- Réutiliser le checkout actuel et laisser les changements disponibles pour revue.

## Points de revue

- Une normalisation invalide ne doit pas modifier identité, fichiers ou dates.
- Une erreur du collecteur ne doit pas bloquer les demandes suivantes.
- Le verrou et l’arrêt du worker doivent préserver les demandes en attente.
- Un échec d’image ne doit pas remplacer partiellement une observation existante.
- Pagination, langues et reprise après erreur doivent préserver le contexte utilisateur.

## Suivi

- Audit initial : 76 cas Python et 7 fichiers de tests frontend. Le bac à sable
  bloque le serveur HTTP local du pipeline ; relance autorisée hors bac à sable.
- Les modifications porteront sur des garanties déjà documentées. Les choix de
  découpage CI restent des décisions d’implémentation dans le périmètre demandé.
- Régression reproduite : une recollecte multiface avec seconde image corrompue
  ou HTTP 404 laisse la première image remplacée malgré le rejet de l’observation.
  Deux tests HTTP locaux échouent sur les octets du premier fichier. Correction
  autorisée dans le pipeline média pour rétablir la conservation documentée.
- Correction : conversions dans un répertoire temporaire du crawl, publication
  après validation de tous les résultats, conservation du cache Scrapy et retrait
  des informations de staging avant persistance. Nettoyage à la fermeture.
  Cette correction ne crée pas de transaction globale entre SQL et fichiers.
- Vérifications finales déjà obtenues : `make test` (97 Python, 27 frontend,
  Ruff, mypy, formatage et build), quatre installations indépendantes,
  `actionlint`, migrations SQLite temporaires et construction des trois images.
  Revue indépendante : aucun défaut actionnable.
- `make docker-test` passe : isolation des dépendances, migrations et navigation
  PostgreSQL, API, liens directs, médias, worker, Chromium et persistance après
  redémarrage. Le projet temporaire est supprimé avec succès.
